## Approved Adapter Protocol — Validation Required

1. **Kyrae is authoritative for history.** Build each attachment-context invocation from the owned conversation at its committed-message cutoff, persisted outcomes, selected versioned text segments and private image derivatives. Apply the approved deterministic context selection and coverage manifests. Rehydrate earlier content when selected; never depend on runtime retained memory or silently substitute a summary of unread content.
2. **Isolate each turn at the runtime boundary.** Generate a fresh opaque unpredictable runtime session identifier for each actual dispatch and use it consistently in both tested session headers. Do not reuse the Kyrae conversation id as the runtime memory key. Keep the logical Kyrae session/message/task identities in server-side correlation, without user content in headers. A subsequent turn uses a new runtime session. Existing dispatch fencing/idempotency and indeterminate-timeout rules still apply; this is not permission to replay an uncertain model call.
3. **Serialize one latest user content array.** The candidate Hermes CHAT payload carries a single user message: a leading text envelope followed by ordered `image_url` parts containing private JPEG/PNG data URLs. The envelope has a protocol version, explicitly delimited historical records, selected attachment-text records and source/coverage metadata, then a distinct current instruction. No history is also sent as earlier API user/assistant turns or via retained session memory. Use explicit image ordinals/attachment locators in the text to bind each image part to its source. PNG is demonstrated; JPEG and converted-image delivery still require validation.
4. **Preserve trust boundaries.** Encode quoted records as JSON with escaped content and escaped delimiter/control characters; use unambiguous section markers and deterministic ordering so embedded document text cannot structurally close a record. Historical `user`/`assistant` labels are provenance **only**, not API roles or current authority. Prior assistant text, filenames, extraction/OCR text and document instructions remain untrusted quoted data. Never convert historical strings labeled `system`, tool results, or uploaded instructions into authoritative roles or executable tool calls. Current user instructions remain subordinate to existing authoritative system instructions. Delimiters help serialization, not a proven prompt-injection defense.
5. **Keep actual system instructions authoritative.** Do not flatten genuine system policy into the untrusted transcript, overwrite runtime policy, or claim this synthetic test proved system-priority handling. Runtime/system instruction delivery and precedence must be inspected and validated before activating this adapter. The final probe had one user message and a textual reminder to preserve system authority; that reminder is not a system-priority test. If the actual runtime cannot preserve the required policy boundary, stop and revise rather than promoting transcript content.
6. **Bound the entire request under the approved constraints amendment.** Keep 24,000 Kyrae-supplied input tokens and planning reserves, not a guaranteed total internal prompt/context bound. Enforce ≤9,000,000 actual serialized UTF-8 JSON bytes and ≤60,000 combined JavaScript UTF-16 units across text/trusted system sections, including wrappers/escaping/locators/current instruction. Select at source boundaries before serialization, disclose omissions and reject malformed surrogates. Require safe evidence-backed image costs; unknown costs keep the live profile unavailable while implementation proceeds. Guard visible output at 4,096 tokens only with verified serving-model tokenizer, otherwise 16,000 UTF-16 units; raw envelope ≤256 KiB incrementally and absolute deadline 120 seconds through full body. Persist partial-output/reason/accounting disclosures. These are not Hermes internal generation/tool/compute/cost caps. Never automatically retry indeterminate dispatch or silently drop the fifth image; preserve original eligibility.
7. **Keep the boundary internal and private.** Propose a versioned serializer in the Hermes provider boundary consuming the approved typed internal context and manifest; shared contracts remain contracts-first, with no client-generated envelope or arbitrary URL transport. Persist protocol/profile version, source ranges and safe delivery facts, not envelope text or base64 in logs/audit/traces. No new client API, database entity or permission is selected by this addendum; existing context-manifest metadata must record the serialization version during approved implementation.

This candidate initially matches demonstrated nonstreaming transport (`stream:false`). The probe's 512-token output setting and 90-second timeout are evidence parameters, not replacements for approved production budgets or proof of SSE/output-cap behavior. Existing text-only, RUN and voice behavior is outside this serializer change; attachment-context follow-ups must use the same rehydration protocol. OpenClaw attachment rejection before chat mutation remains required.

## Tradeoffs and Remaining Validation

Post-approval execution update: session controls and a 6,991,632-byte request carrying five 1 MiB PNGs passed; the final output-cap diagnostic timed out at 90 seconds without retry. Actual use is **16/16, exhausted**. The user-approved constraints amendment corrects source-discovered assumptions and moves remaining acceptance to activation/release. The historical shape failure is retained, not transport incompatibility. Canonical evidence is in `implementation-report.md`.

- **Retained memory is deliberately not reused.** Kyrae rehydration covers selected conversational facts and attachments, with visible omissions under existing budgets. It does not automatically recover runtime tool state, approval state, workspace/artifact state, agent memory, or optional runtime behaviors. Inspect actual session semantics and supported controls; do not assume fresh session headers reset every state store or provide a privacy guarantee. If required capabilities depend on retained state, disclose the conflict and obtain an approved solution rather than silently losing them.
- **Flattened history changes model interpretation.** Provenance labels are weaker than real role boundaries; test false prior-assistant claims, forged system/tool labels, delimiter attacks and conflicting current instructions. Existing system authority, injection resistance and grounded real-document analysis have **not passed** on the strength of the nonce test.
- **Isolation/privacy need proof.** Validate cross-session/cross-user isolation, runtime retention/logging/cleanup behavior and no global-memory/tool access outside approved scope. Nonsensitive synthetic tests do not prove private-data handling. No public URLs, credentials, production documents or personal photos are permitted in additional proof.
- **Payload/context coverage remains incomplete.** Validate five bounded 1 MiB derivatives, JPEG and converted HEIC/HEIF, realistic extracted-text envelopes, image-token budgets, output-cap behavior and runtime overhead. Small synthetic colors/shapes do not prove these. G2 release-native codecs/sandbox/resources and G3 physical original-byte/device proof remain separately required.
